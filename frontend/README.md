# ContribMatch frontend

React 19 + Vite + TypeScript + Tailwind CSS v4 + React Router + Axios + Recharts + Lucide.

```bash
cd frontend
npm install
npm run dev        # http://localhost:5173  (proxies /api -> http://localhost:8000)
npm run build      # type-check + production build
npm run lint
npm test           # Vitest + Testing Library (jsdom)
```
Start the backend first (see `backend/README.md`). The browser only talks to the FastAPI backend, never to GitHub,
so no GitHub token ever reaches the frontend.

## Pages
| Route | Page |
|---|---|
| `/` | Landing: how it works, the scoring formula, honest limitations |
| `/profile` | Developer profile setup (skills, languages, domains, learning interests, experience level) |
| `/dashboard` | Real recommendations with filtering, sorting, score breakdown and links to GitHub |
| `/analytics` | Charts computed by the backend from stored history (lazy-loaded) |
| `/history` | Past runs; open one to revisit it |

## Structure
```
src/
  api/         axios client, error normalisation (ApiError), endpoint functions
  types/       TypeScript interfaces mirroring the backend responses
  context/     SessionProvider: saved profile + last run id (localStorage, this browser only)
  hooks/       useResource (fetch + retry)
  lib/         filters/sorting, formatting, safe GitHub URL check, form suggestions
  components/  Navbar, Sidebar, AppShell, ProfileForm, SkillSelector, RecommendationCard, ScoreBreakdown,
               FilterPanel, AnalyticsCharts, LoadingState, EmptyState, ErrorState, ...
  pages/       Landing, ProfileSetup, Dashboard, Analytics, History, NotFound
  test/        tests + fixtures (see below)
```

## Notes
- No recommendation, statistic or chart value is hard-coded. Everything comes from the API. The landing page only
  documents the (fixed) scoring weights.
- Issue titles are rendered as text, and links are only created for `https://github.com/...` URLs.
- `src/test/fixtures/*.json` are real responses generated by the backend code with its test doubles, used to test
  the UI against true response shapes. They are not shown in the app.
- Layout is responsive via Tailwind breakpoints (sidebar becomes a slide-over menu below `lg`; the filter panel
  collapses below `lg`). Tests cover the mobile menu behaviour, but pixel-level layout has not been checked in a real browser.
